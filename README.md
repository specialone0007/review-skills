# Review Skills

[![CI](https://github.com/specialone0007/review-skills/actions/workflows/ci.yml/badge.svg)](https://github.com/specialone0007/review-skills/actions/workflows/ci.yml)
[![skills.sh](https://skills.sh/b/specialone0007/review-skills)](https://skills.sh/specialone0007/review-skills)

Seven review skills that make any `SKILL.md`-compatible agent file the same report every time: findings ranked P0–P3, each one anchored to a `path:line` you can open.

Claude Code already ships strong first-party review — a built-in `/security-review`, an official `code-review` plugin, and a security-review GitHub Action — and this does not try to out-detect any of them. What it adds is the shape around them: one consistent, evidence-first output format across seven distinct review dimensions, five of which no first-party review tool covers at all. The same seven skills run unchanged in Codex, Cursor, and Copilot CLI, where the Claude-only tooling does not run, and each ships an `agents/openai.yaml` so it appears as a properly named action in Codex rather than an untitled prompt.

Every audit skill is read-only by default. It reports; it does not edit, until you explicitly ask for fixes.

```bash
npx skills add specialone0007/review-skills --skill '*'
```

Then just ask:

```text
audit my repo for launch risks
security audit this repo
what tests am I missing
```

Given no scope, every audit surveys the whole repository, ranks surfaces by risk, inspects the riskiest in depth, and tells you what it only skimmed. Name a feature, route, PR, or branch and it narrows to that instead.

## Example output

This one is real. It is `docs-sync-audit` run against this repository, quoted from
[examples/docs-sync-audit.md](examples/docs-sync-audit.md):

```markdown
1. **P2: The README says CI runs the skills validator on Windows. It only runs on Ubuntu.**
   Drift: `README.md:116` reads "CI runs both, on Ubuntu and Windows." Only
   `validate_evals.py` runs on both. `validate_skills.py` runs in a single-OS job.
   Impact: a contributor trusts that a Windows-only path bug in `validate_skills.py`
   would be caught by CI. It would not be.
   Evidence: docs `README.md:116`; source `.github/workflows/ci.yml:18`.
   Suggested update: add the matrix to the `validate` job and leave the README alone.
```

That finding was correct, and it is fixed in the same commit that added these examples —
the `validate` job now runs on both platforms. [examples/](examples/) holds a full report
for every one of the seven skills, each generated by pointing it at this repository. Clone
it and re-run any of them to compare.

## The seven skills

Install one, or all of them:

```bash
npx skills add specialone0007/review-skills --skill docs-sync-audit   # just one
npx skills add specialone0007/review-skills --skill '*'               # all seven
```

Each heading links to a real report that skill produced against this repository. The
quoted phrase is what you say to trigger it — you do not have to match it exactly, it is
a description rather than a command.

### `feature-audit` — launch readiness and bug risk

> *"audit my repo for launch risks"* · [see a real report](examples/feature-audit.md)

The broad one. Traces user journeys, alternate states, data and permission boundaries,
then reports what would bite you after shipping. Given no scope it surveys the whole
repository and ranks surfaces by risk.

Reach for a specialist below instead when the question is narrower.

### `security-audit` — auth, exposure, and abuse paths

> *"security audit this repo"* · [see a real report](examples/security-audit.md)

Auth, authorization, injection, secrets, data exposure, dependencies. Every finding names
the abuse path, not just the smell. Bundles a dependency and supply-chain survey that
reports install hooks, unpinned and non-registry specs, and missing lockfiles without
contacting any registry unless you allow it.

Not a general bug hunt.

### `test-gap-audit` — which behaviour is not covered

> *"what tests am I missing"* · [see a real report](examples/test-gap-audit.md)

Not how to write a test in your framework — *where coverage is missing across the
repository*, in any language. Bundles a mapper that matches every source file to tests by
name, by mirrored path, and by what the test files actually import, then ranks the
unmatched by risk keyword and size. It also flags test files that have cases but almost no
assertions.

It never runs your tests.

### `docs-sync-audit` — where the docs stopped matching the code

> *"check the docs against the code"* · [see a real report](examples/docs-sync-audit.md)

Documented commands that no longer exist, links that no longer resolve, environment
variables the docs promise but nothing reads. Bundles a checker for the machine-verifiable
half so the agent spends its attention on the prose.

It catches one thing a name comparison cannot: a documented setting that *is* read by the
code, but only inside a module nothing imports — configuration that reads as working and
cannot take effect.

### `repo-health-audit` — structure, duplication, dead code

> *"is this codebase getting messy"* · [see a real report](examples/repo-health-audit.md)

Naming drift, weak module boundaries, duplicated logic, catch-all directories, files that
have outgrown their place. Bundles an inventory script so the audit starts from a
measured picture of the repository instead of a guess.

Structure only — not runtime behaviour.

### `feature-brainstorm` — ideas, not defects

> *"what could we improve here"* · [see a real report](examples/feature-brainstorm.md)

Improvement opportunities grounded in what the code actually does, each with effort and
confidence, plus an explicit list of what it decided *not* to pursue. Given no surface it
picks the one to three highest-leverage ones and says why, rather than dumping ideas
repository-wide.

The only skill here that is not looking for problems.

### `pr-branch-summary` — PR and release communication

> *"write the PR description for this branch"* · [see a real report](examples/pr-branch-summary.md)

A PR title, a description, and a team message drafted from the real diff rather than from
commit messages. Bundles a script that collects the git evidence in one pass.

The one skill that touches git state, and only ever to fetch a single missing base ref.

Each skill names its nearest neighbours in its own `## Related Skills` section, so an
agent can route itself if you pick the wrong one.

## Compared to first-party tooling

| | First-party (Claude Code) | Review Skills |
| --- | --- | --- |
| Bug and security detection | `/security-review`, the official `code-review` plugin, security-review Action. Use them. | Not a replacement. Same class of finding. |
| Report shape | Varies by tool and run | One contract: P0–P3 severity plus `path:line` evidence, no finding without both |
| Dimensions covered | Security, correctness, performance, maintainability | Those, plus test-coverage gaps, documentation drift, repo structure and duplication, improvement ideation, and PR communication |
| Runs in Codex, Cursor, Copilot CLI | No | Yes, unchanged, with Codex interface metadata |
| Cost | Built in on paid plans | MIT, no server, no account |

If you only use Claude Code and only want security and correctness findings, use the first-party tools. This exists for the other five dimensions, and for teams whose agents are not all Claude Code.

## Install

With the `skills` CLI:

```bash
npx skills add specialone0007/review-skills --skill '*'          # all seven
npx skills add specialone0007/review-skills --skill feature-audit # just one
```

As a Claude Code plugin:

```text
/plugin marketplace add specialone0007/review-skills
/plugin install review-skills@review-skills
```

Or copy a skill folder into your agent's skills directory:

```text
.claude/skills/<skill-name>/
.agents/skills/<skill-name>/
.github/skills/<skill-name>/
.cursor/skills/<skill-name>/
~/.codex/skills/<skill-name>/
~/.cursor/skills/<skill-name>/
```

Each folder holds a `SKILL.md`, an `agents/openai.yaml` with Codex interface metadata, and, for most of them, a bundled read-only Python script that uses only the standard library. Scripts are accelerators; every skill still works without them.

## Safety

All seven skills are read-only on your files by default. They instruct the agent not to edit, stage, or commit anything unless you explicitly ask for fixes or implementation.

One precise exception: `pr-branch-summary` may run `git fetch origin <base>` when the base branch you asked to compare against is missing locally. That updates a single remote-tracking ref and never touches your working tree, index, or local branches. It is skipped when the ref already exists.

To authorize implementation, ask explicitly — "fix these findings", "add the suggested tests", "update the stale docs".

As with any third-party agent skill, read the skill contents before enabling it in a trusted environment. Everything here is plain Markdown plus a handful of small standard-library Python scripts, so it is quick to audit.

See [CONTRIBUTING.md](CONTRIBUTING.md). Before opening a PR:

python tools/validate_skills.py   # spec limits and repo conventions
