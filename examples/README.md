# Examples

> **This document owns:** what the example reports are, how each was produced, and what they are evidence of.

Real runs of each skill against **this repository**, at commit `cc100ad` (`docs-structure`, added later, at the head of its own pull request).

Nothing here is illustrative or hand-written. Each report is what the skill actually produced, citations included, and you can re-run any of them yourself and compare:

```bash
npx skills add specialone0007/review-skills --skill '*'
git clone https://github.com/specialone0007/review-skills && cd review-skills
# then ask your agent the prompt from the table below
```

| Skill | Prompt used | Report |

| `docs-structure` | is our docs folder organised | [docs-structure.md](docs-structure.md) |
| `docs-sync-audit` | check the docs against the code | [docs-sync-audit.md](docs-sync-audit.md) |
| `feature-audit` | audit my repo for launch risks | [feature-audit.md](feature-audit.md) |

## A note on what these show

These were generated by pointing each skill at this repository and committing the result unedited. Several findings in them are real, and some were fixed in the same change that added these files -- `feature-audit` in particular found a missing UTF-8 guard in a bundled script, a README claim that did not match CI, and a missing `## Related Skills` section.

That is the point of publishing them: a report you can check beats a report that reads well.
